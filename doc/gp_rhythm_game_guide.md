# 霓虹节拍 · 2K / 4K 音游

支持 Windows 和 Android。触屏直接点击霓虹轨道，按谱面自动采用 2K / 4K，支持多指同时敲击、同轨交替连打和长按（含 sub 与尾判定）。每个手指绑定按下时的轨道，滑出轨道不切换，抬起或系统取消触摸才释放；同轨其他手指或键盘仍按住时保持长按。菜单、失焦及停止演奏会清理按压状态。触屏复用现有音频时钟、输入补偿、判定、敲击音效和高亮；Auto 不接收手动敲击。Android 实机延迟仍需在音画校准中按设备调节。

## 曲库资产包

正式曲目来自独立资产包的 manifest.json：special_type 为 rhythm_library，songs 列出曲目 .tres/.res 的包内相对路径。music_game.tscn 不再预绑歌曲；正式回合按房主的候选曲库元数据构建随机池，再异步加载选中的一首。详见框架 [曲库制作与导出指南](../../../../doc/api/external_resources.md)。

推荐目录为 music/ 保存音源、charts/<曲目>/ 保存 song.tres、各难度 .tres 和 JSON。目录是制作规范，不做硬性结构检查；正式发现只读取声明列表。曲目使用公共 PartyMusicSong（core/api/music/party_music_song.gd），music 绑定一份 AudioStream，charts 绑定 PartyMusicChart 资源。每个谱面资源填写 difficulty、chart_path（res:// JSON 路径）、base_score（默认 1,000,000）。资源名 resource_name 是曲目显示名。

曲库不能依赖小游戏脚本。原创示例迁入 games/assets/gp_rhythm_original/；Bad Apple 短版和完整版在 games/assets/gp_rhythm_bad_apple/，由主仓库 .gitignore 整包排除，但本地编辑器仍可发现。源音乐和第三方谱面仍未确认再发行许可。

房主把霓虹节拍加入房间池后，匹配类型的可用曲库进入开局依赖检查；客机额外安装的曲库不参与本局。所有候选曲库需要版本/构建匹配，下载更新后仍须重启。PCK 和音频不在此元数据检查阶段加载；选中曲目时才挂载所属包并后台读取资源。不会预载所有歌曲。

每轮房主从本机累计次数最少的候选曲目中随机抽取，用回合种子打破平局；同步稳定 ID“资产包 ID/曲目资源路径”。客户端晚加载时请求当前选择，重复消息不重抽。准备页允许每位玩家独立选择绑定的难度；曲目先以列表第一项建立初始准备数据。

真正进入演奏时，本机记录一次，准备期间退出不计数。主机、客机和观战端各自保存 minigame/gp_rhythm_game/config/song_pool_stats.json，--party-profile 隔离多实例数据。曲库增删保留历史，新曲从零开始；退役 ID 不参与抽取。损坏数据或写入失败明确结束本局，不自动清零。

单人制作测试仍可扫描曲库中的 JSON 并组成临时曲目，无需每次重新导出。JSON 的 audio_file 可使用 res:// 路径访问 music/，正式玩法以曲目资源绑定的音乐和谱面资源的难度/基准分数为准。源 JSON 不会因游戏选曲而改写。

## 单人计分

判定窗口为 PERFECT ±50 ms、GOOD ±100 ms、OK ±150 ms，包含边界；超出窗口为 MISS。判定质量分别为 1.00、0.65、0.30、0。

最终分数为 `round(base_score × 准确率)`，准确率在公式中取 0～1，采用与 HUD／联网报告一致的百分比小数点后两位。例如基准分数 1,200,000、准确率 95% 时得分 1,140,000。基准分数读取曲目 Resource 所选难度条目，不再按难度名称附加倍率或对准确率平方。独立 JSON 测试和编辑器预览使用默认基准分数。演奏 HUD 和独立练习结算的主数值仍为准确率；正式对局按得分排名，同分并列，退出者不参与排名，结算表包含得分、准确率和最长连击。房主使用已锁定难度的本地资源计算得分，不接受客户端自报基准分数。

普通音符总权重为 1，获得其判定质量；长按总权重为 1.5，头部获得判定质量，完整按到尾部再获得头部质量的 0.5 倍，中断则不获得尾部权重。Sub 保持连击、判定反馈和音效，但不参与准确率权重；连击不加分。空敲击不得分。

HUD、排行榜与结算显示实时准确率：已获得权重 / 已判定权重，开局尚无判定时显示 100%。未到来的音符不计入分母，MISS 计入分母但不获得权重；长按头部判定计入 1，尾部完成或中断时再计入 0.5，Sub 不影响准确率。判定数量和最长连击仍包含 Sub、尾点，因此不能用这些数量直接还原准确率。编辑器预览每次定位/循环清空计分，只统计所选区间内的音符起点；跨过区间起点的长按只继续播放，不补计分。

演奏画面右侧居中显示排行榜。轮换中展示实际参赛者；独立练习保留占位，校准界面隐藏排行榜。

## 界面主题

`ui/rhythm_theme.tres` 是音游、音画校准和原生制谱编辑器共用的 Theme：深蓝面板、青色选中状态、统一下拉菜单、滚动条、输入框、复选框和弹窗。编辑器默认 18px；单机测试和校准控制面板复制主题并采用 24px 基础字号，不会修改共享资源。主游戏的主题、HUD 字号与布局直接保存在场景中，运行时不再覆盖；主要操作按钮使用 `RhythmPrimary` 主题变体。

字体使用原版协议 `font_sans` 对应的 `NotoSansSC-UI.otf`。同一文件和许可证保存在 `assets/fonts/`，保持音游目录自包含，不要求运行时安装协议包。主题图标位于 `ui/icons/`，均为本项目绘制的 SVG。主题调整后重新运行场景即可。

## 可移动目录与发布边界

本目录保存音游场景、字体、音效和制作工具；音乐与谱面由独立曲库资产包提供。动态谱面/音效路径通过 `rhythm_paths.gd` 从包内脚本位置解析。运行仍依赖 GodotParty 的公开 API 和原版协议，不是另一个独立 Godot 工程；安装包 ID `gp_rhythm_game` 保持不变，显示名称为“霓虹节拍”。

在 Godot 编辑器中打开 `authoring/single_player_test.tscn` 并 F6 可选曲试玩；制作工具扫描标记为 rhythm_library 的资产包中的 charts/ 与 music/。新位置需要先由 Godot 完成正常资源导入。

制谱时在 Godot 编辑器中打开 `authoring/chart_editor.tscn`，按 F6 运行当前场景；主游戏使用 `music_game.tscn`，选曲试玩使用 `authoring/single_player_test.tscn`，音画校准使用 `authoring/calibration_test.tscn`，均按 F6 运行。原生界面复用常驻霓虹舞台，编辑与游戏共享谱面、音效及校准配置，不需要外部启动脚本或 Web/Python 后端。操作见 [制谱说明](gp_rhythm_game_authoring_guide.md)。原生保存恢复副本放在 `charts/.editor_recovery/`（不进入 Git）。

编辑和预览均由原生 Godot 场景完成，Web 页面、HTTP 后端和 Web 导出链路已移除。

原版协议的小游戏轮换可选「霓虹节拍」。支持 1–8 名参赛者，加载当前曲目后由各玩家选择难度并准备，再直接进入演奏。客户端按本地音频时钟判定，成绩每 0.4 秒更新至排行榜。房主按最终准确率（百分数保留两位）排名，同分并列，最长连击作为展示指标。断线未完赛者退出排名，曲终 20 秒后仍未回报的玩家按退出处理。观战者可查看本轮排名。

音效来源随包保存在 [音效来源](gp_rhythm_game_assets_audio_candidates_sources.md)，字体与各音效许可证保留在对应资产目录；歌曲和谱面来源见 [Bad Apple 来源](../charts/bad_apple/SOURCE.md)。

## 配置与生命周期

正式对局由 `settings.gd` 声明本包偏好，并在 `party_setup` 注入 PartyConfig。按键、音效、音量和同步参数仅在下次对局激活时读取，比赛中打开菜单不会重置时钟。通过框架设置页修改本包偏好；正式演奏不读写作者工具文件，也不访问框架私有配置实现。两类设置使用同一组默认值，但持久化相互隔离，不自动导入旧原型设置。

`ui/playback_audio.tscn` 固定保存 Track、TapPreview、四轨 Tap / HoldStart / HoldSub / HoldEnd 和每轨八个谱面音效声部。动态创建的仅为本实例的四条声像总线；离开时回收。停止对局会停止全部音频，断开 Auto 的 process_frame 和本包网络/玩家信号；重复停止不会重新播放或重复提交。输入释放和成绩读取分别通过后端 `release_inputs()`、`performance()` 完成。

共享协议回合页面 G01 和专用播放器的协议音量作用域 G03 尚待统一改造，本包没有复制协议混音器，也没有改用通用音频句柄驱动判定；目前本包音乐/敲击增益仍由自身音量控制。原生编辑器、单机测试和独立校准界面统一保留在 `authoring/`，仅用于开发；正式游戏继续共享音频、判定和设置实现。

三个独立场景均可在编辑器中直接 F6：

- `music_game.tscn`：主游戏界面，仅包含霓虹舞台、HUD、排行榜占位和停止／结算界面。通过 Inspector 的 `song` 绑定曲目 Resource、`difficulty` 选择其难度，独立运行时自动开始；被其他场景嵌入时由调用方控制开始。
- `authoring/single_player_test.tscn`：单机测试界面，负责谱面选择、刷新、Auto、跳过前奏、音效与改键设置，嵌入主游戏界面完成演奏。
- `authoring/calibration_test.tscn`：音画校准测试界面，复用主游戏舞台并提供听音采样、补偿调整和保存。可从单机测试进入，也可单独运行。

游戏、测试与原生编辑器统一显示完整动态效果；非完整效果开关和渲染分支已删除。`rhythm_backend.gd` 继续负责共用的音频时钟、判定和设置。正式轮换入口为 `party_round.tscn`，结算由原版协议交回大游戏。

### 手工调整画面

- 打开 `music_game.tscn` 可直接调整 `HUD` 下的标题、准确率、连击、判定、时间误差和排行榜节点；锚点随窗口缩放，脚本只更新实时内容和显隐，不重写位置、字号与样式。旧的隐藏介绍、最佳连击和重复准确率节点已移除。
- `Modal` 默认隐藏，避免遮住编辑画面。`ui/results.tscn` 是实际演奏结束后显示的结算页，`ui/pause.tscn` 是停止面板，可分别打开调整；主场景直接实例化这两份资源。
- `Backdrop/NeonStage` 直接实例化 `skins/neon.tscn`。舞台通过 `@tool` 在编辑器中显示静态背景、轨道和判定区；打开皮肤场景可调整颜色，`editor_key_count` 仅用于预览 2K / 4K。运行时轨道数仍由谱面决定，编辑器中不启动音频或判定。背景与轨道仍由 `skins/neon.gd` 绘制，不是独立图片节点。

- 开始 / 重来：4 拍预备拍，随后 64 拍测试；普通模式含少量八分音符，听音校准为均匀四分拍。
- 默认演奏按键：4K 从左到右 D / F / J / K；2K 左轨 D、F，右轨 J、K。同轨双键可重叠交替连打，每次独立按下立即判定，没有额外敲击冷却；同一按键需松开后再按，键盘自动重复不判定。长按持续至该轨全部按键松开；长按期间额外按键不会重复触发头部。菜单“音效与按键”及原生编辑器设置均可分别修改 2K / 4K 按键；点击按键后录入新键，Esc 取消，重复键会提示冲突。应用并保存后共用本地设置；取消恢复修改前配置。编辑数字输入框时不判定游戏输入。
- 画面提前量：正值使音符提前到线，只改变画面，不改变判定。
- 按压延迟补偿：正值从按压时刻扣除毫秒数，补偿稳定的偏晚输入。
- 下落时间只影响视觉速度；BPM 在下一次开始时生效。补偿可实时预览，比较成绩前应重开。
- F6、单机测试、校准和制谱工具只在“应用并保存”时写入安装根目录的 `minigame/gp_rhythm_game/config/authoring.json`。恢复默认和采用建议均不自动保存；旧原型用户文件不再读取。
- 切换窗口停止本轮，回来重新开始，不带着过期时钟继续。

## 调校步骤

1. 在单机测试菜单点击“音画校准”，或直接 F6 运行 `authoring/calibration_test.tscn`，默认用霓虹舞台显示均匀节拍音符。勾选“听音采样（隐藏音符）”后，使用实际游玩设备和音频输出，按左轨当前绑定（默认 D / F）跟随短音敲击至少 16 次；此模式不播放敲击音效。
2. 建议值使用最近最多 32 次有效敲击的原始误差中位数，显示中位绝对偏差衡量稳定性。采用建议后重开复测。
3. 关闭听音校准，调画面提前量，使音符到线和听到短音重合。
4. 调整下落时间，查看正式 HUD 的 EARLY/LATE 误差及面板的采样稳定性。点击“应用并保存”写入与游戏、原生编辑器共用的设置；停止或本轮结束后可直接重测，返回选曲不会自动保存。

听音校准只能估计设备延迟和个人敲击习惯的合成偏差，不是硬件测量；高抖动、蓝牙音频或不稳定节拍应多轮复测。输入校准采样窗口为 ±240 ms，普通判定为 PERFECT ±50 / GOOD ±100 / OK ±150 ms。正误差为晚，负误差为早。

## 同步实现与边界

测试音频是程序生成的原创 PCM，不下载外部资产。声音提示直接写到每个音符时间对应的采样点；没有逐帧播放节拍定时器。

时钟 = AudioStreamPlayer.get_playback_position() + AudioServer.get_time_since_last_mix() - 输出延迟估计；每轮重新读取延迟，钳制音频线程导致的小幅倒退。输入事件发生时重新采样同一时钟，不使用累计 delta。声音输出和显示器的实际延迟仍需实机校准；按键事件精度受操作系统与帧调度限制。

支持版本 3 JSON 双键 tap / hold 谱面及配套 OGG：`key_count=2`、`note_type="tap_hold"`，`notes_ms` 为绝对毫秒，`lanes` 与其等长，0 为左、1 为右。按时间和轨道升序排列，允许同刻左右同时音符，拒绝同轨同刻重复。`durations_ms` 与音符数组等长：0 为单击，正数为长按持续毫秒；同轨音符不可进入长按占用区间（含尾时刻），异轨不受限。当前无在线同步或自动播放。舞台中每次逻辑按压触发预生成的 45ms 原创敲击声，空按也发声；同轨别名、长按和自动重复不会重复触发，左右双押可叠加。BGM、成功敲击、空敲击音量在菜单“音效设置”中独立调节、试听和保存；听音校准模式不播放敲击声。歌曲与判定仍使用原音频时钟，敲击声是独立反馈。设备切换后停止并重开。

参考：https://docs.godotengine.org/en/stable/tutorials/audio/sync_with_audio.html

## 可选本地 Bad Apple!! 谱面测试

两个 Bad Apple 曲目目录仅供本地选曲，独立仓库默认提供原创练习曲。点击开始播放整首，或点击“从首音前 3 秒测试”跳过约 14 秒无音符前奏。跳过前奏只改变起播位置，谱面仍使用绝对音频时间。歌曲 BPM 不受合成 BPM 控件影响，播放至音源结尾后完成。

下拉选择支持 Easy（287 音符）、Normal（532 音符）、Hard（704 音符）及合成节拍。Normal 对应原谱 Medium；三种难度共用配套音源。切换会停止当前播放并清空本轮音符和成绩，保留按压补偿、画面提前量等调校参数；点击开始进入所选难度。Bad Apple 三档按原左/下列映射左轨、上/右列映射右轨；跨轨同刻音符保留双押，同轨重合合并，节奏时点与音源保持原样；双轨合成测试左右交替，听音校准仍在左轨使用均匀节拍。谱面与音源的作者、原文件和转换规则见 charts/bad_apple/SOURCE.md。

旧谱面转换回归脚本已退役，不再作为当前谱面格式的验证入口。

旧双轨 UI 测试已退役。左右轨隔离、双押、校准、结束和失焦行为按当前实现定向验收。

判定区与到线音符同宽，中心位于判定线；按压闪光约 220ms 后消退，轨道纵深渐变在长按期间持续显示。

音效设置中的成功敲击与空敲击可独立选择默认合成音或 12 个 Virtuosity Drums CC0 架子鼓音效（长尾镲片单独标注），支持试听、取消恢复与应用保存；音效 ID 保存到本地配置，来源见 `doc/gp_rhythm_game_assets_audio_candidates_sources.md`。

敲击素材统一混为居中单声道；左右轨分别采用 -0.15 / +0.15 的轻微声像偏移，试听居中，BGM 不受影响。

长按：开始、每个 sub、结束均独立计分与连击。头部使用输入补偿与原判定窗口，按住至尾部自动 PERFECT，无需松手；提前松手使剩余 sub 和尾部 MISS，已获得的分数保留。不会靠重按补回断掉的长按。`subs_ms` 是与音符数组等长的嵌套数组，内部时间为绝对音频毫秒，严格递增且必须位于头尾之间；tap 使用空数组。帧跳跃会补处理已到时节点，重复帧不重复计分。

音效设置新增“长按开始 / 长按 Sub / 长按结束”三路，分别选择、试听、调节音量并应用保存。舞台播放沿用各轨左右声像，试听居中；开始音效不会叠加普通成功敲击音效。长按体内白色短横条表示尚未触发的 sub。

菜单第五项“长按专项测试 / Start · Sub · End”：独立原创 25 秒节拍音源与 JSON 谱面，16 条音符、66 个判定节点，包含单侧长按配异轨 tap、双轨同时长按、250ms 密集 sub。Bad Apple 原谱保持单击安排。

“Bad Apple!! / 制谱初稿”：独立音频辅助编排，包含 tap、hold、sub。在 Godot 编辑器中运行 `authoring/chart_editor.tscn`，从谱面库选择打开、新建、删除、保存或另存为；保留波形、拍分吸附、拖动编辑、循环试听和同音源参考对比。保存后回到选曲菜单或点击“刷新”即可发现新谱面，重新开始该曲读取音符修改。空谱可保存为编辑草稿，但不会进入游戏选曲。操作说明见 [制谱工作台](gp_rhythm_game_authoring_guide.md)。

音量滑块现支持 0–200%，保存范围为 0–2；BGM / 校准节拍统一乘以 0.4 的基准增益，试听与游戏一致。已有音效补偿和独立音量保留。

开始与重新演奏在音乐前加入默认 5 秒的静音前置时间，谱面立即载入，时间从 -5 秒推进；倒计时内照常刷新音符、接收输入、执行 Auto 和原有判定，首拍可以提前下落并在正常判定窗口内被敲击。跨越音乐第 0 秒不重建音符、不清空判定或按住状态；ESC 或失焦取消待播放音乐。静音段使用单调时间推进，按输出延迟和下一次混音时间提前提交音乐，随后沿用音频播放位置时钟和原有校准；不修改谱面时间。`music_game.gd` 的导出属性 `preparation_seconds` 可调为 0–15 秒（0 跳过）；启用“从首音前 3 秒开始”时，在所选音频起播位置之前加入同样的前置时间。

选曲下拉菜单限制为 280 像素高度，超出时使用滚动条/滚轮选择。现有鼓点 Easy 加入镲片重音与 16 条短长按，不另增难度版本。

制作统一在 Godot 编辑器中运行 [authoring/chart_editor.tscn](../authoring/chart_editor.tscn)。当前辅助生成采用离线 MIDI 规则，说明见 [authoring/MIDI_RULES.md](gp_rhythm_game_authoring_midi_rules.md)。A–E 旧实验工具及对应谱面已移除，手工谱面和当前 MIDI 试验保留；霓虹是唯一美术实现。

菜单勾选 **AUTO 自动演奏（测试）** 后开始：自动处理单击、双押、长按 Start/Sub/End，使用当前音效选择、音量和左右声道设置，播放对应命中特效。Auto 默认关闭，不持久化；舞台与结果页标明 AUTO。可用 `set_auto_play(true/false)` 或启动前的导出属性 `auto_play` 设置，修改在下一局生效；取消勾选后重新开始即可恢复手动。

Auto 用原音频时钟和输入补偿调度，在后端每帧漏判检查前按顺序注入音符的目标时间；校准、判定函数和谱面数据不变。卡帧时补齐跨过的头、sub、尾，不重复计数。音效仍在实际处理帧播放，因此 Auto 适合试听谱面和反馈，不用于测量真实输入延迟。自动演奏期间 A/D 与方向键不参与判定；准备阶段仍可空敲，ESC/失焦仍停止本轮。

音效设置新增 191 个 [FluidR3 代表器乐 WAV](gp_rhythm_game_assets_audio_candidates_fluid_r3_sources.md)，涵盖 120 种 GM 音色、49 个额外音区和 22 种小打击；保留现有鼓、镲及合成短敲，总计 204 项。五类敲击均可独立选择、试听、保存，Web 编辑器继续继承游戏配置。逐项文件见 [音色目录](gp_rhythm_game_assets_audio_candidates_fluid_r3_catalog.md)。这些是离线渲染的单声道 PCM 音效，游戏没有引入 MIDI 播放器。

## 完整版 MIDI 4K

谱面库选择 **BadApple_完整版_MIDI_4K**：5:17 完整原曲，138 BPM，网格起点 1308 ms，6891 个单击、0 长按、18 种代表乐器 WAV。最多同刻四押，不限制难度；超出四种声音时优先鼓和钢琴。同刻同音色合并，MIDI 缺少的一段 8 小节重复乐句已补齐，音频不拉伸。来源、对齐证据及生成规则见 [完整版说明](../charts/bad_apple_full/SOURCE.md)。

本地另存的 **BadApple_短版_MIDI_4K** 使用既有 `bad_apple/bad_apple.ogg`（3:37.705），保留 4819 个单击和 15 种器乐音效。根据两份音源的波形匹配，保留完整版工程第 `[0,64)`、`[128,352)`、`[384,511)`、`[639,结束]` 拍，分别按音源差异平移，再吸附至 1/64 网格；138 BPM、网格起点 83.5 ms。相对分段音频映射的额外量化误差不超过 7.42 ms，不代表实机总延迟。轨道和逐点音色沿用完整版，完整版工程与两份音源保持不变。短版与原测试素材同属本地未确认再发行许可内容，不随 Git 发布。

音效设置默认启用“使用谱面指定音效”，没有指定的节点仍按音符类型选择音效；关闭后全部回到按类型发声，空敲始终使用空敲设置。各类型音量和轨道声像仍生效。逐点音效用编辑点的可选 `sound` ID 保存，跟随移动、换轨和复制；运行谱面编译为 `hit_sounds: [{time_ms, lane, sound}]`，只允许对应实际判定节点，同节点不可重复。每轨使用 8 个轮换声音保留音尾；密集连击超过容量时替换最早轮换的声音。当前没有逐点音色选择面板，可用生成器或编辑工程 JSON 指定。

1–8 人同场演奏，各自选择难度，按基准分数 × 准确率排名。

### 开发文件与发布边界

本包 `export_ignore.txt` 使用 Git ignore 语法，排除 authoring/ 和旧 charts/ 本地历史；不使用 `.gdignore`，在 Godot 中正常显示并导入。谱面编辑器入口为 `authoring/chart_editor.tscn`，单机测试和独立校准场景也在同目录，SM 转换工具为 `authoring/convert_sm.py`。直接在 Godot 文件系统面板打开对应 `.tscn`，按 F6 运行。

已停用的 Kenney 候选和 Virtuosity 原始 FLAC 位于 `authoring/audio_candidates/`；运行时仅使用原路径的 WAV 和现用 FluidR3 音效，署名与许可证继续随正式素材发布。

### 曲目音乐绑定规范

每个曲目版本只维护一份正式歌曲文件，推荐保存在曲库 music/。PartyMusicSong.music 与工程 JSON 的 audio_file 应引用同一份音源；所有难度共享它，不嵌入音频或复制歌曲。工程 JSON 保存 res:// 音源路径，曲目资源绑定各难度 .tres，谱面资源再绑定 JSON。这是作者约定，不新增音源一致性检查。

更换工程音乐后，作者须同步曲目资源的 music。保存现有 JSON 保持路径，改显示名不会破坏绑定；另存得到新 JSON 后，需要手动创建/调整谱面资源和歌曲绑定。包内未使用的正式文件仍会收集，候选素材应放 authoring/ 或由 export_ignore.txt 排除。
