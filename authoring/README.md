# DUET 制谱工作台

在 Godot 编辑器中打开 **`chart_editor.tscn`，按 F6（运行当前场景）** 启动制谱工作台。上一级 **`single_player_test.tscn`** 用于选曲试玩，**`music_game.tscn`** 为主游戏界面，**`calibration_test.tscn`** 用于音画校准；均可按 F6。它们均为普通可运行场景，不需要外部启动脚本、Python 后端或 Web 导出。

原生界面使用 Control 绘制时间轴，SubViewport 内常驻同一个霓虹舞台。音符修改、跳转和循环只更新谱面与播放状态；复用游戏的音频时钟、Auto、判定、长按/Sub、WAV 音效库和配置解析。波形通过独立解码器分批生成，不读取或推进正在播放的音源实例。静止时只在内容/视野变化时重画时间轴；高密度点通过时间索引裁剪。


工作台自动扫描 `../charts/` 下的 v3 谱面。原生版默认打开排序后的第一份工程，下拉选择即可切换；新建时选择 2K / 4K。已有工程不自动改写，逐音符音效和来源字段保持。A–E 旧实验工具及对应谱面已移除。

Python 文件仅供离线制谱与音色渲染使用，不作为编辑器或游戏的启动入口。MIDI 生成参数见 [MIDI 规则说明](MIDI_RULES.md)。

## 谱面文件操作

- **打开**：原生版在谱面库下拉框选择工程名即打开。列表支持滚轮；“刷新库”更新列表而不丢弃当前修改。
- **新建**：选择库内音乐文件，填写工程名、音乐名、音乐作者、谱面作者、难度、额外备注，创建空白谱面。支持先保存空草稿；至少有一个有效音符后才进入游戏选曲。
- **保存 / Ctrl+S**：写入当前打开的 JSON，包括音符与 BPM / 网格起点。原谱也可以编辑；希望保留原版时请先“另存为”。
- **另存为**：复制当前编辑内容到新文件并切换到它，保留相同音源，不覆盖原文件。重名会拒绝写入。
- **删除谱面**：原生版确认后把当前 JSON 移到 `charts/.editor_recovery/<时间_标识>/`，不删除音源；替换保存和改名也保留原文件。需要恢复时将 JSON 放回对应音源目录并刷新。恢复目录被 Git 忽略，请勿当作永久备份。
- 切换、新建、关闭前有未保存修改时提示放弃或取消；需要保留先 Ctrl+S。原生保存比较打开时的源文本，其他程序有改动时拒绝覆盖，需重新打开或另存为；不计算文件哈希。

工程信息仅有六项：`project_name`（工程名）、`title`（音乐名）、`artist`（音乐作者）、`mapper`（谱面作者）、`difficulty`（难度）、`remarks`（额外备注）。工程名用于库列表和标题；文件名由工程名生成，连续空格转为一个下划线，自动添加 `.json`，例如 `Bad Apple 鼓点练习` → `Bad_Apple_鼓点练习.json`。支持中文；拒绝路径符号、Windows 保留名称与重名覆盖。工程名不填写扩展名。

修改工程名后按 Ctrl+S会重命名文件，并将原文件保留到上述恢复目录；“另存为”生成独立工程。名称不同但转换后文件名相同也算重名。导出 JSON 使用同一命名规则。谱面作者和备注允许留空。既有谱面未设置工程名时以现有文件名作为初始工程名；打开不写文件。键数在新建工程时选择；格式版本、音符数组与来源信息属于运行/溯源数据，不作为工程标注。

其他歌曲：原生版“导入音乐”复制 WAV / Vorbis OGG 到 `charts/<文件名>/`，同名文件拒绝覆盖。也可自行放入目录后刷新。音源与 JSON 必须同目录；原生编辑器和游戏共用音频加载方法，支持新复制、尚未导入的 WAV / OGG。“更换音乐”保留拍子位置，若音符超出新音乐末尾会拒绝修改。工作台不负责下载歌曲，也不支持其他音游的谱面格式直接导入。

保存后回到 Godot 选曲菜单或点击选曲旁的 **刷新**，即可载入新增、删除和改名后的谱面；重新开始该曲读取音符改动。音画同步、校准和判定逻辑不变。

## 编辑

- 谱面的 `key_count` 决定 2K / 4K；新建时选择键数，打开后自动显示对应轨道。当前没有将已有谱面自动合并或拆分轨道的转换操作。
- 4K：Q/W/E/R 切换四轨单击，A/S/D/F 切换长按标识。2K 使用 W/E、S/D。长按标识按轨道、时间两两配对，中间单击自动成为 Sub；落单标识可保存。同轨同拍同类删除、异类覆盖。
- ←/→ 移动吸附光标，越界翻页；[ / ] 切换 1/1～1/64 吸附。滚轮缩放，Ctrl+滚轮平移，中键拖动视野。
- 左键空白框选，Shift+点击增减选择。拖动选中点或框选边界内可整体移动，垂直拖动跨轨，保持相对拍位置和轨道间距；触碰轨道边缘时整组限制，目标同拍位置被覆盖。M 镜像翻转（4K 为 1↔4、2↔3）。
- Ctrl+C / X / V 使用系统剪贴板复制、剪切、粘贴独立编辑点；粘贴以当前光标对齐最早的点，保留相对拍数与轨道，选中粘贴结果。四轨内容粘贴到两轨时，若越界则拒绝整次操作，不静默丢点。
- Ctrl+A 全选，Delete 删除，Ctrl+Z 撤销，Ctrl+Shift+Z 或 Ctrl+Y 重做；Ctrl+S 保存。输入框保留原生文字编辑快捷键。
- Shift+F / Shift+G 在同时选中的长按两端之间填充 / 清空 Sub。删除头尾不会删除其他独立点。
- Space 按选定模式播放 / 暂停；I/O 将光标设为区间起止点，终点 0 表示歌曲末尾。Esc 停止，拖动时取消本次移动；F1 查看快捷键。
- 歌曲总览位于预览上方；左右分栏可以拖动调整。工程信息、音效与同步、统计对比使用弹窗。按钮和滚动下拉列表不会占用键盘焦点；数字输入完成后 Enter 返回编辑光标。细分线延续 Web 版的粗细、透明度、短刻度与 1/32、1/64 点线，可分别隐藏。
- 音画补偿、音效选择和音量继续继承游戏设置。光标试听保持 120ms 短片段，正式播放时停用。音频时钟、判定窗口及长按/Sub 规则不变。
- 游戏手动演奏按键：2K 为 A/D 或 ←/→；4K 为 D/F/J/K。编辑器快捷键不改变游戏演奏按键。

原生预览按三种模式启动：从吸附光标、起止区间（蓝/红标记，可循环，终点 0 表示末尾）、从头（5 秒前摇）。负起点额外静音段与游戏一致。Space 暂停后可从暂停光标继续；改变模式后按该模式重新起播。音效与同步弹窗的试听只临时修改当前实例；确认写入游戏现有的 `user://party/prototypes/rhythm_1k.json`，取消还原。没有迁移或重置原来的校准设置。运行宿主工程内的场景已经验证；独立可执行文件导出和硬件实际端到端延迟需要另行验收。

## 初稿如何制作

`author.py --generate` 使用 numpy + soundfile：读取现有 OGG → 单声道分析 → 对数频谱正向差分提取起音强度 → 在明确指定的 138 BPM 下拟合拍点相位 → 按 8 小节乐句模板、起音强度和双轨占用规则编排 tap/hold/sub。

这是 **音频分析 + Codex 设计规则的辅助初稿**，没有运行生成式神经网络，也没有将原谱音符喂给生成器。138 BPM 是音乐先验，算法没有证明它是唯一正确速度；73ms 是模一拍的网格相位，不是音频延迟。长按是乐句安排，不宣称检测到了真实延音。初稿约从 13.986 秒开始至 208.769 秒结束，首尾保留空白。

若需复现生成，先在自己的 Python 环境安装 `numpy soundfile`，然后运行 `python author.py --generate`。已有初稿会拒绝覆盖；只有明确要丢弃人工编辑时才使用 `--generate --force`。日常启动编辑器仅需 Python 标准库，无需这两个分析依赖。

## 鼓点 Easy（含前奏）

鼓点 Easy 独立保存于 `authored_easy.json`。从唯一工作台入口打开后，在谱面库选择 `authored_easy` 即可精调，不需要另开服务。

这版用 35–180Hz 与 1800–9000Hz 两个频带的正向能量变化筛选鼓点候选，沿用 138 BPM / 73ms 网格；没有参考原谱选点，也没有使用鼓声分离模型，所以高频旋律瞬态仍可能被选中。以每两拍一次为骨架，只有明显重音补充孤立四分音符，底鼓倾向左轨、镲片倾向右轨，允许同声部重复按同一轨；补入孤立高频重音，并用少量短长按表达镲片衰减，不安排双押；本轮在强起音的半拍位置补入短三连，并加入长按 sub 与尾段延音。频带阈值用于控制两手负担，不能保证每个候选都是真实鼓或镲。

本次继续更新同一个 Easy 文件，不新增难度入口：

- 保留普通段的鼓／镲声部分轨；按四小节选取明显半拍起音，安排 23 组三个八分音符的左右左／右左右，间隔约 217ms，同手回击仍有约 435ms。
- 22 条长按包含 37 个自动 sub，通常每拍一个；很短的长按仅设中点 sub。sub 需要保持按住，不需要重新敲击，仍使用已有独立音效与连击规则。
- 约 187.899–208.769 秒安排 7 条短延音长按，另一手保留部分鼓点；最后一条右轨长按从 **208.769 秒至 215.508 秒**，约 **6.739 秒**、15 个 sub，覆盖鼓点结束后的持续声与收尾。
- 尾段是参考混合音频频谱、持续声和网格做的人工乐句编排，没有分离人声；最后吟唱的起点、尾音仍需结合实际听感精调。长按同轨前后保留至少 300ms 恢复，不把尾音后的混响无限延长。
- 5 秒准备空段与音画同步、自动尾判逻辑不变。总计 383 次主动按下、442 个判定节点。前奏新增 N 连击后，当前实测峰值为每秒 6 次，只作统计，不再限制峰值或总起点数。


参考：[osu!mania mapping guide](https://github.com/ppy/osu-wiki/blob/master/wiki/Guides/osu%21mania_mapping_guide/en.md)。采用同类声音保持编排一致、重音强调乐句、长按对应持续声响、Easy 控制密度与手负担的建议；本项目尾判自动完成，不照搬 osu!mania 的松手判定。

### 开头 N 连击试验

138 BPM 下，四分音符约 434.783ms，八分音符约 217.391ms，十六分音符约 108.696ms；二分音符为两拍，约 869.565ms。“半拍”指八分音符，不叫“半分音符”。三个连续八分音符也不等于三连音。

对现有 OGG 前奏做频谱正向变化检查：1.376 / 1.486 / 1.593 / 1.704 / 1.811 秒有五个明显起音，与十六分网格的误差约 0–2ms；4.853–5.291 秒重复同类音群。按当前共享网格编排，不移动音频或输入校准。

- 十六分 **5 连击**：约 1.377、4.856、8.334、11.812 秒起，左右交替，轮换起手；包含落点的第五击。
- 八分 **3 连击**：约 3.116、6.595、10.073、13.551 秒起，按音群做左右左／右左右。
- 每组后保留音乐原有空隙；普通整拍仍沿用鼓／镲声部分轨。替换前 14 秒中的一条短长按，避免它挡住连击。
- 只修改前 14 秒；后续鼓点、三连击、sub 和最后吟唱长按沿用上一版。实际听感与手感仍需游戏试听；起音分析不是乐器分离。
# Godot 舞台预览

`stage_preview.tscn` 是原生编辑器内部常驻的霓虹舞台，支持未保存音符热修改与范围循环 Auto。运行 `chart_editor.tscn` 后自动加载，无需单独启动。

编辑以拍数为准：1 拍＝四分音符，第 0 拍位置由音频偏移指定。范围终点 0 表示歌曲末尾；[ / ] 切换 1/1～1/64 吸附，所有光标定位均吸附。轨道中键拖拽反向平移视野，滚轮以编辑光标缩放，Ctrl＋滚轮平移。BPM / 起点修改会重算已有音符（含长按和 sub）的音频时间，并支持撤销。保存包含精确拍数以及供游戏使用的毫秒数组。
